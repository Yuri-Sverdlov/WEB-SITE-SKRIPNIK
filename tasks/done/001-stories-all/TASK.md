## Что сделать

### 1. Страница `src/pages/StoriesAll.tsx`

Заменить заглушку полноценной страницей.

**Запрос данных (первая страница, сортировка):**

```typescript
supabase
  .from('stories')
  .select('*', { count: 'exact' })
  .order('published_at', { ascending: false })
  .range(from, to)
```

- `PAGE_SIZE = 15`
- Для страницы `page` (0-based): `from = page * PAGE_SIZE`, `to = from + PAGE_SIZE - 1`
- Обработать `error` (показать короткое сообщение пользователю, не падать молча)
- Пока загрузка — простой индикатор («Загрузка…»)

### 2. Список карточек

На каждый рассказ — карточка (Tailwind, аккуратно, без макета):

- **Заголовок** (кликабельный)
- **Дата публикации** — формат для ru, напр. `toLocaleDateString('ru-RU')`
- **Просмотры** — число из `views`
- **Теги** — список/чипы; если `null` или пусто — не ломать вёрстку

**Каждая карточка** — ссылка на `/stories/:id` (`react-router-dom` `Link`, `id` из записи).

### 3. Пагинация

Внизу списка две кнопки:

- **«Назад»** — предыдущая страница (disabled на первой)
- **«Вперёд»** — следующая страница (disabled, если записей больше нет)

Использовать `.range()` в запросе Supabase (не резать массив на клиенте после `select('*')` без range).

При смене страницы — новый запрос с нужным `range`.

Опционально: строка «Страница N» — по желанию, не обязательно.

### 4. Scope — не трогать

- `StoryDetail.tsx`, другие страницы, `App.tsx` (роут уже есть)
- `Home.tsx` (тестовый `console.log` Supabase — не удалять, если не мешает)
- `AGENTS.md`, `CONTEXT.md`, `PROJECT_LOG.md`

Новые файлы — только если реально нужны (тип `Story` можно объявить в `StoriesAll.tsx` или `src/api/types.ts`).
