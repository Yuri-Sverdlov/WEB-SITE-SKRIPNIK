## Цель

На **`StoryDetail`**: автор сайта видит **«Ответить»** под **комментарием читателя**; ответ сохраняется с **`is_author_reply = true`** и **`parent_id`**, показывается **под** этим комментарием с пометкой **«Ответ автора»**. Ответ на ответ **не нужен**.

---

## Контекст

- Схема из **0005:** `comments.parent_id` → `comments(id)` on delete cascade; один уровень вложенности.
- Триггер **`enforce_write_rate_limit`:** для **`is_admin()`** при ответе принимает `is_author_reply` / `parent_id` и подставляет подпись из **`author_display_name()`** («Александр Скрипник»). Читатель не может подделать ответ автора с фронта.
- Сейчас `fetchComments` / `ReaderMessageList` — **плоский** список без `parent_id` (см. комментарий в `comments.ts`).
- Кто автор UI: **`useIsAdmin()`** (как «Кабинет» в шапке). Кнопки модерации — только в `/admin` (TASK-015).

---

## Что сделать

### 1. API (`src/api/comments.ts` или отдельный модуль)

- Расширить **`fetchComments(storyId)`**: выбирать `id, author_name, body, created_at, parent_id, is_author_reply` (и `story_id` при необходимости).
- **`insertAuthorReply(input)`** — insert от вошедшего автора:
  - `story_id`, `user_id` (auth), `body`, `parent_id` = id комментария читателя;
  - передать `is_author_reply: true` (триггер для автора сохранит; для читателя RLS/триггер обнулят — не использовать для читателя).
  - **Без** поля «имя» в форме — подпись задаёт БД.
  - Валидация текста: 1–2000 символов (как у читателя).
- Ошибки — через `mapReaderMessageError` / русские тексты.

### 2. Отображение на `StoryDetail`

- Построить дерево **одного уровня:** корневые комментарии (`parent_id` null), ответы автора (`is_author_reply`, `parent_id` = id корня) — **под** родительским комментарием, с отступом или вложенным блоком.
- У ответа — метка **«Ответ автора»** (или подпись из `author_name`, если совпадает с `author_display_name()`).
- **Не показывать** «Ответить» под: ответом автора, комментарием, у которого уже есть ответ автора (один ответ на комментарий — уточни в REPORT, если в БД несколько разрешены; продуктово достаточно скрыть кнопку после первого ответа).

### 3. UI ответа (только `isAdmin`)

- Под комментарием читателя — ссылка/кнопка **«Ответить»**.
- По клику — компактная форма: textarea + «Отправить» / «Отмена» (inline или под комментарием).
- После успеха — обновить ленту комментариев.
- Гость и читатель **не видят** «Ответить».

### 4. Scope — не трогать

- SQL, миграции.
- `/admin` модерация, `reader_profiles` — **TASK-017**.
- Гостевая книга — без ответов автора.
