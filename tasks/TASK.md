## Цель

Закрыть **подделку служебных полей** при INSERT читателя: клиент не должен задавать `created_at` в прошлом (обход rate limit, ложные даты) и **`is_author_reply = true`** на комментариях (до этапа 8–9).

**RLS** по-прежнему проверяет только **`user_id = auth.uid()`** — это не меняем в этом TASK; дополнительно **зафиксировать проверку (b)** из брифа.

---

## Контекст

- Триггер **`enforce_write_rate_limit`** (0003) считает записи за последнюю минуту по **`created_at`**. Если клиент передаёт старый `created_at`, лимит 3/мин обходится.
- Колонка **`comments.is_author_reply`** есть в БД; UI её не шлёт (008), но **PostgREST/console** может.
- **`increment_story_views`**: SECURITY DEFINER без `search_path` (замечание в 0001) — hardening отдельно в этой миграции.

**Фронт не трогаем**, если не обнаружится регрессия (не ожидается).

---

## Что сделать

### 1. Миграция `supabase/migrations/0004_harden_reader_inserts.sql`

Идемпотентно: **`CREATE OR REPLACE`** функций.

**1.1. `enforce_write_rate_limit()`**

В начале тела триггера, **до** `count(*)`:

- `NEW.created_at := now();` — для **обеих** таблиц (`comments`, `guestbook_entries`).
- Для **`comments`** additionally: `NEW.is_author_reply := false;`  
  (на `guestbook_entries` колонки нет — не трогать).

Остальная логика rate limit и русские сообщения — **без изменения смысла**.

**1.2. `increment_story_views(story_id_input uuid)`**

Добавить **`SET search_path = public, pg_temp`** (тело UPDATE как в 0001).

Комментарий в файле: миграцию **применяет только пользователь** в SQL Editor; кодер в прод не деплоит.
