# Бриф консультанта → архитектор. Блок G (короткий): 5 рассказов вручную и подготовка к показу

**Дата:** 2026-10-12
**Заменяет** прежнюю версию брифа G (с программой переноса). Вопросы архитектора из `docs/Документ1.pdf` по программе — **сняты**.

## Решение пользователя

Сайт — сюрприз для Скрыпника. Сейчас: **дизайн + 5 рассказов, перенесённых вручную** через кабинет. Программа автоматического переноса, иллюстрации внутри текста и перенос остальных рассказов — **отложены** до разговора со Скрыпником.

Работаем как в D–F: TASK кодеру → приёмка архитектора → push после подтверждения пользователя. SQL применяет только пользователь. Один отчёт консультанту в конце: `tasks/consultant-block-G-report.md`.

## G0 (TASK-025): хвосты блока F + миграция 0010

Миграция `0010_*.sql`:
1. В `enforce_admin_update_hidden_only()` пропускать служебные роли (`current_user in ('postgres','service_role','supabase_admin')`), чтобы изменения из SQL Editor проходили. Читателям это ничего не открывает (UPDATE закрыт RLS). Записать в `docs/DEVELOPER.md`.
2. Колонка `stories.source_url text` (**без UNIQUE**, необязательная) — для G1.

Проверки:
- скрыть комментарий с ответом автора → гость и читатель не видят **ни комментарий, ни ответ**; «Показать» → видят оба;
- изменение комментария из SQL Editor проходит; читатель через консоль по-прежнему не может менять `is_hidden`;
- два снимка: `/admin/comments` и страница рассказа с ответом автора.

## G1 (TASK-026): ссылка на Проза.ру и удобная вставка текста

1. **Поле «Ссылка на Проза.ру»** в редакторе рассказа (необязательное, проверка: адрес начинается с `https://proza.ru/` или `https://www.proza.ru/`).
2. **Строка на странице рассказа**, если ссылка заполнена — под текстом, перед отзывами:
   «Этот рассказ опубликован на сайте Проза.ру. Там же вы можете увидеть более ранние рецензии.» — **вся фраза** — ссылка на `source_url`, `target="_blank"`. Текст — в `src/config/site.ts`. Нет ссылки — нет строки.
3. **Очистка текста при сохранении:** `\r\n` → `\n`, неразрывные и прочие невидимые пробелы → обычный пробел, пробелы в начале и конце строк убрать, несколько пустых строк подряд схлопнуть. Абзац = строка (логика TASK-024).
4. **Теги:** при вводе — подсказки из уже существующих тегов; сохранять строчными, без лишних пробелов, без повторов.

## G2: перенос 5 рассказов (делает пользователь, не кодер)

После G1 пользователь переносит вручную через кабинет:

| Название | Тег | Дата и время (Москва) | Ссылка |
|---|---|---|---|
| Эффект Манделы | ироническая проза | 19.09.2026 19:52 | https://proza.ru/2026/09/19/1674 |
| В Древней Греции полдень горяч | юмористическая проза | 05.07.2026 09:01 | https://proza.ru/2026/07/05/567 |
| Куралес | фантастика | 04.02.2016 22:08 | https://proza.ru/2016/02/04/2397 |
| Зеленый свет | миниатюры | 29.04.2023 11:04 | https://proza.ru/2023/04/29/626 |
| Альманах | рассказы | 23.03.2026 06:55 | https://proza.ru/2026/03/23/340 |

Число прочтений вписывает автор (поле есть). Архитектор даёт пользователю короткую памятку: что куда вставлять.

**Время — всегда московское (входит в TASK-026):**
- в редакторе подпись «Дата и время публикации (московское)»; введённое значение сохраняется как `+03:00`, при открытии рассказа показывается тоже по Москве — независимо от пояса компьютера автора;
- на сайте дата и время выводятся по Москве (`timeZone: 'Europe/Moscow'`). Читатели в других поясах пересчитывают сами.

## G3 (TASK-027): доводка дизайна на настоящих текстах + уборка

**Не начинать до G2** и списка замечаний пользователя (или «дизайн ок»). Скриншоты и docx — **в том же TASK-027**, одним заходом.

3. Обновить скриншоты в `reference/screens/` (главная, рассказы, страница «Куралеса» со строкой про Проза.ру).
4. Инструкция автора (`docs/Instruktsiya_dlya_avtora.docx`): раздел «Как перенести рассказ с Проза.ру вручную».

## Проверки конца блока

- 5 рассказов на сайте: название, дата-время, тег, абзацы, строка со ссылкой на Проза.ру — сверяет пользователь.
- Вставка текста с лишними пустыми строками и невидимыми пробелами сохраняется чисто; теги не дублируются («Фантастика» = «фантастика»).
- Проверки G0.
- build и lint без новых ошибок; в репозитории нет паролей и ключей.
