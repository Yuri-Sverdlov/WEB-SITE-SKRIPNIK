## 1. Как работаем (как в D и E)

- Архитектор код **не пишет**. Каждая подзадача — отдельный TASK кодеру. Приёмка — архитектор (build, lint, ревью, браузер). Push — после подтверждения пользователя.
- SQL к базе применяет **только пользователь**.
- **Особенность блока F:** оформление оценивает глаз. После F1 и после F3 — **обязательная остановка на просмотр пользователем** (скриншоты). Дальше — только после его «да».
- Консультанту — один отчёт в конце блока: `tasks/consultant-block-F-report.md`.

## 3. Подзадачи

### F0 (TASK-018): хвосты блока E и исправление фамилии

1. **В git:** папка `docs/` (`DEVELOPER.md`, `Instruktsiya_dlya_avtora.docx`) и `tasks/final-acceptance-E.md`.
2. **Порядок удаления рассказа** (`deleteStory`): сначала удалить рассказ в базе, потом файлы картинок. Сейчас наоборот — при сбое остаётся рассказ без картинок.
3. **Проверка защиты на живой базе:** пользователь прогоняет скрипт из `final-acceptance-E.md`, часть 1 (тестовым читателем, консоль браузера). Таблицу результатов — в отчёт блока E.
4. **Миграция `0008_author_name_fix.sql`:**
   - `author_display_name()` → `'Александр Скрыпник'`;
   - в `reserved_author_names` добавить: `скрыпник`, `skrypnik`, `skripnik` (старые записи оставить — «скрипник» тоже должен быть запрещён читателям);
   - уже сохранённые ответы автора (`comments` с `is_author_reply = true`) — обновить подпись на новую.
5. **Тексты:** «Скрипник» → «Скрыпник» в `docs/DEVELOPER.md`, `docs/Instruktsiya_dlya_avtora.docx`, `CONTEXT.md`, ТЗ, интерфейсе. Технические имена (репозиторий `WEB-SITE-SKRIPNIK`, проект Vercel) **не трогать**.

**Проверка:** ответ автора под комментарием подписан «Александр Скрыпник»; читатель не может взять имя «Скрыпник», «скрипник», «Skrypnik».

### F1 (TASK-019): снять стиль с образцов → направление дизайна

1. На ПК2 запустить **Dembrandt** по двум образцам (Node есть; браузер для него ставится командой `dembrandt install-browser`):
   ```
   npx dembrandt https://evgeny-yakubovich.art/ --design-md --screenshot
   npx dembrandt https://www.akunin.ru/main.html --design-md --screenshot
   ```
   Результаты — в `reference/yakubovich/` и `reference/akunin/`.
2. По результатам — `reference/design-direction.md`, одна страница:
   - палитра: фон, текст, акцент, ссылки, служебный серый (4–6 цветов);
   - **шрифты с хорошей кириллицей**: шрифт с засечками для текста рассказов, второй для меню и заголовков (может совпадать). Подключение — Google Fonts или файлы в проекте;
   - ширина колонки текста (ориентир 60–70 знаков в строке), интерлиньяж, размер основного шрифта (не меньше 18 px — читатели не молодые);
   - что берём у каждого образца и что сознательно **не** берём.
3. Те же значения — в `tailwind.config.js` как тема (цвета, шрифты), чтобы дальше все страницы брали их из одного места.
4. **Остановка:** одна тестовая страница (например, страница рассказа) в новом стиле → скриншот → пользователь смотрит. Дальше — только после его «да» или правок.

### F2 (TASK-020): каркас — шапка, меню, подвал, вкладка

- Шапка: **«Александр Скрыпник — рассказы»** (ведёт на главную).
- Меню по-русски: **Об авторе** (главная) · **Рассказы** · **Гостевая книга** · **Связь**. Справа — вход/выход, «Кабинет» для автора.
- Убрать служебные пункты меню: `StoriesNew`, `StoriesPopular`, `StoriesAll` (вкладки остаются внутри раздела «Рассказы»), **`StoryDetail`** (ведёт на несуществующий `/stories/example`).
- Подвал: © год, имя автора, email (из той же константы).
- Заголовок вкладки браузера: «Александр Скрыпник — рассказы»; на странице рассказа — «<Название рассказа> — Александр Скрыпник». Иконка вкладки (favicon) — простая, без картинки автора.
- Убрать все английские подписи из интерфейса (проверка поиском по коду).

### F3 (TASK-021): страница рассказа — удобное чтение

- Подключить плагин `@tailwindcss/typography` (класс `prose` сейчас ничего не делает — плагин не установлен).
- Колонка текста, шрифт, интерлиньяж, отступы абзацев — по `design-direction.md`.
- Над текстом: название, дата, число прочтений, теги — спокойно, мелко, не спорят с текстом.
- Иллюстрации — по ширине колонки, с отступами.
- Комментарии и ответы автора — визуально отделены от текста рассказа; «Ответ автора» заметен, но не кричит.
- **Остановка:** скриншоты страницы рассказа (длинный текст + комментарии с ответом автора) → пользователь смотрит.

### F4 (TASK-022): «Об авторе» (главная) и «Связь»

- **Об авторе:** имя, место под фото (аккуратная заглушка, легко заменить), утверждённая биография, ниже — **3–5 последних рассказов** со ссылками и ссылка «Все рассказы».
- **Связь:** короткая фраза + email из константы. Без формы.
- Тексты биографии и фразы для «Связи» — в одном файле с константами (не размазаны по разметке), чтобы на сайтах №2–3 менять одно место.

### F5 (TASK-023): единый вид остальных страниц

- Списки рассказов (три вкладки, поиск, пагинация), гостевая книга, вход, регистрация, формы сообщений — в той же палитре и шрифтах.
- Кабинет автора — **без украшательства**, но в общей палитре и шрифтах, аккуратно и читаемо.
