## 1. Как работаем (как в блоке D)

- Архитектор код **не пишет**. Каждая подзадача — отдельный TASK кодеру (DeepSeek V4.1 Flash, терминал).
- Приёмка каждого TASK — архитектор: build, lint, ревью кода, проверка в браузере. Push — **после подтверждения пользователя**.
- SQL к базе и настройки Supabase (Storage, Auth) применяет **только пользователь**. Кодер пишет файл `supabase/migrations/NNNN_*.sql`, архитектор даёт пользователю путь и точные шаги, пользователь возвращает вывод SQL Editor.
- Консультанту — **один отчёт в конце блока**. Раньше — только при блокере, противоречии с ТЗ или если нужно решение пользователя.

## 2. Решения пользователя (зафиксированы)

| Вопрос | Решение |
|---|---|
| Кто автор | Обычный аккаунт Supabase + права автора, выданные одной SQL-командой. Сейчас — аккаунт пользователя (Yuri, тестирует), через 1–2 месяца — Скрипник. Передача прав = та же команда, без изменения кода |

## 3. Принцип безопасности

Настоящая защита — **в базе**: RLS, триггеры, политики Storage. Проверка «автор ли» в интерфейсе — только удобство. Каждое право автора должно быть закрыто в базе для всех остальных, и это проверяется в конце блока (раздел 5).

## 4. Подзадачи

### E0 (TASK-011): права автора, защита и бан — в базе

Миграция `0005_author_role.sql`:

1. **Роль автора.** Таблица `site_admins` (`user_id` → `auth.users`, PK). Функция `is_admin()` (SECURITY DEFINER, `search_path` задан): true, если `auth.uid()` есть в `site_admins`. Читатели не могут читать или менять `site_admins`.
2. **stories:** INSERT / UPDATE / DELETE — только `is_admin()`. Чтение — как сейчас (всем).
3. **comments, guestbook_entries:** DELETE — только `is_admin()`.
4. **Ответы автора.** В `comments` колонка `parent_id` (nullable, → `comments(id)` on delete cascade). Один уровень вложенности.
5. **Триггер `enforce_write_rate_limit`** (из 0004) расширить:
   - `is_author_reply` и `parent_id`: для не-автора принудительно `false` / `null`, для автора — как прислал;
   - автор освобождён от лимита 3 сообщения в минуту;
   - **запрещённые имена:** таблица `reserved_author_names`, заполнить списком из раздела 2. Перед сравнением нормализовать имя: нижний регистр, ё→е, латинские двойники → кириллица (a c e o p x y k m t b h → а с е о р х у к м т в н), обрезка пробелов. Сравнение по вхождению. Ошибка на русском;
   - **бан:** если `auth.uid()` есть в `banned_users` — отказ с текстом «Вы не можете оставлять сообщения на этом сайте».
6. **Бан.** Таблица `banned_users` (`user_id`, `banned_at`, `reason`). Читать и менять — только `is_admin()`.
7. **Удаление всех сообщений читателя.** Функция в базе (только `is_admin()`): удаляет все комментарии и записи гостевой книги указанного `user_id` одним действием и возвращает число удалённых. Отдельная функция (или режим той же) возвращает **только счёт**, без удаления, — для окна подтверждения.
8. **Прямые ссылки на Vercel.** В репозитории нет `vercel.json`. У SPA прямой переход на `/stories/<id>` или F5 на `/admin` может давать 404. Читатели приходят по прямым ссылкам, поэтому это критично. Проверить на развёрнутом сайте: открыть ссылку на рассказ в новой вкладке и нажать F5. Если 404 — добавить `vercel.json` с переадресацией всех путей на `index.html`.

**Пользователь после применения 0005** (архитектор даёт точные команды):
- выдать права своему аккаунту: `insert into site_admins … where email = '<его email>'`;
- убедиться, что `reserved_author_names` заполнена.

### E1 (TASK-012): каркас /admin

- Маршрут `/admin`: не вошёл → `/login` с возвратом; вошёл, но не автор → «Нет доступа».
- Меню: Рассказы / Комментарии / Гостевая книга / Заблокированные.
- Ссылка «Кабинет» в шапке — только для автора.

### E2 (TASK-013): рассказы

- Список всех рассказов с поиском. Создать / редактировать / удалить (удаление — с подтверждением).
- Форма: заголовок, текст (textarea с абзацами), дата публикации, теги, **начальное число просмотров** (нужно для переноса с Проза.ру, ТЗ §3).
- После сохранения — переход на страницу рассказа.

### E3 (TASK-014): иллюстрации

- Bucket `illustrations` в Supabase Storage: чтение всем, запись и удаление — только `is_admin()` (политики `storage.objects`). Создаёт пользователь по инструкции архитектора.
- В форме рассказа: загрузка нескольких картинок, превью, удаление. Только изображения, не больше 5 МБ. Путь: `stories/<story_id>/<uuid>.<ext>`.
- При удалении иллюстрации или рассказа удалять и файлы из Storage.

### E4 (TASK-015): модерация и бан

- Ленты: комментарии (новые сверху, со ссылкой на рассказ) и гостевая книга.
- У каждой записи — **всегда**:
  - «Удалить» (эту запись) — с подтверждением;
  - **«Заблокировать читателя»** — поле «причина» (необязательное), сообщения не трогает;
  - **«Удалить все сообщения читателя»** — сначала окно подтверждения с числами: «Будет удалено N комментариев и M записей гостевой книги. Ответы автора на эти комментарии тоже будут удалены. Продолжить?». Удаление — одним вызовом функции из E0 п.7, не циклом запросов из браузера.
- Блокировка и удаление независимы.
- Страница «Заблокированные»: имя, дата, причина, кнопка «Разблокировать».
- Все кнопки — только в `/admin`.

### E5 (TASK-016): ответы автора

- На странице рассказа автор видит «Ответить» под комментарием читателя.
- Ответ сохраняется с `is_author_reply = true` и `parent_id`, показывается под комментарием с пометкой «Ответ автора». Ответ на ответ не нужен.

## 5. Проверки конца блока

**Автором (вживую):**
- создать, изменить, удалить рассказ с иллюстрациями;
- ответить на комментарий;
- удалить комментарий и запись гостевой книги;
- заблокировать и разблокировать тестового читателя;
- «Удалить все сообщения читателя» — числа в подтверждении совпадают с фактом.

**Приёмочный тест модерации:** через `/admin` убрать тестовый мусор блока D («Тест A», «проверка c1–c3», тестовые записи гостевой — по решению пользователя).

**Тестовым аккаунтом-читателем через консоль браузера** — всё должно быть отклонено или обезврежено:

| | Действие | Ожидание |
|---|---|---|
| a | insert / update / delete в `stories` | отклонено |
| b | delete чужого и своего комментария | отклонено |
| c | загрузка файла в bucket `illustrations` | отклонено |
| d | insert комментария с `is_author_reply = true` и `parent_id` | сохраняется с `false` / `null` |
| e | `author_name` из списка запрещённых | отказ с русским текстом |
| f | забаненный читатель пишет комментарий и в гостевую | отказ; после разблокировки — проходит |
| g | имя «Cкрипник» с латинской C и «АДМИН» | отклонено |
| h | insert в `banned_users`, вызов функции удаления всех сообщений | отклонено |

**Прочее:**
- гость на `/admin` → `/login`;
- прямая ссылка на рассказ + F5 на Vercel — открывается;
- build и lint без новых ошибок.
