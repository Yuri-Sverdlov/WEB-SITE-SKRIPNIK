**Дата:** 2026-10-06

## Зачем

Бан работает по аккаунту (`user_id`) — это верно и остаётся. Но свободное имя в форме даёт два неудобства:

1. Читатель может подписаться именем другого читателя («Вася» пишет как «Маша»).
2. Автор не видит, что «Ностальгия», «Вася» и «Гость» — один и тот же человек.

Решение: имя выбирается **один раз**, закрепляется за аккаунтом, уникально; дальше база подставляет его сама.

## Место в очереди

E0 … E5 (TASK-011…016) → **E6 (TASK-017)** → проверки конца блока + уборка мусора через `/admin`.

## E6 (TASK-017): никнейм читателя

### База — миграция `0006_reader_profiles.sql`

1. **Таблица `reader_profiles`:** `user_id` (PK, → `auth.users`, on delete cascade), `display_name` (2–40 символов после обрезки пробелов), `created_at`.
2. **Уникальность без учёта регистра и двойников букв.** Уникальный индекс по нормализованному имени — та же нормализация, что для запрещённых имён в 0005 (нижний регистр, ё→е, латинские двойники → кириллица, обрезка пробелов). Использовать существующую функцию нормализации из 0005, не дублировать.
3. **Запрещённые имена** (`reserved_author_names`) действуют и на `display_name` — та же проверка, что в 0005.
4. **RLS `reader_profiles`:**
   - читатель видит **только свою** строку; автор (`is_admin()`) — все;
   - INSERT — только своей строки (`user_id = auth.uid()`), один раз;
   - UPDATE / DELETE — никому, кроме `is_admin()`. Сменить имя читателю в MVP может только автор (через SQL или позже через админку — не в этом TASK).
5. **Триггер на `comments` и `guestbook_entries`** (расширить существующий из 0004/0005):
   - не-автор **без профиля** → отказ: «Сначала выберите имя, под которым вас будут видеть»;
   - не-автор с профилем → `author_name := display_name` из профиля, **что бы ни прислал клиент**;
   - автор → как сейчас (подпись «Александр Скрипник» из одной настройки).
6. **Email для автора.** Функция (SECURITY DEFINER, `search_path` задан, только `is_admin()`): по списку `user_id` возвращает `user_id → email, display_name`. Читатели вызвать не могут.
7. **Старые записи** не трогаем: их `author_name` остаётся как было (тестовые всё равно удаляются в конце блока).

### Сайт

- **Первый раз** (вошёл, профиля нет): вместо поля «Имя» в форме — блок «Выберите имя, под которым вас будут видеть. Изменить его потом нельзя». После сохранения — обычная форма.
- **Дальше:** поля «Имя» нет; над формой — «Вы пишете как: <имя>».
- Ошибка уникальности на русском: «Это имя уже занято, выберите другое». Запрещённое имя — текст из 0005.
- Одна логика для комментариев и гостевой книги (общие компоненты из блока D).
- **Админка (модерация, заблокированные):** рядом с именем — email читателя (через функцию из п.6).

## Новые проверки конца блока (добавить к a–h)

Тестовыми аккаунтами-читателями, вживую и через консоль браузера:

| | Действие | Ожидание |
|---|---|---|
| i | Читатель без профиля пытается оставить комментарий (через форму и через консоль) | отказ с русским текстом |
| j | Читатель создаёт профиль и пишет; через консоль шлёт `author_name: "Маша"` | в базе — имя из профиля, не «Маша» |
| k | Второй тестовый аккаунт берёт то же имя другим регистром и с латинской буквой-двойником | «Это имя уже занято» |
| l | `display_name` из запрещённого списка («Скрипник», «Админ») | отказ |
| m | Читатель через консоль: прочитать чужой профиль, изменить своё имя, вызвать функцию email | всё отклонено |
| n | Автор в модерации видит email рядом с именем | да |

Для пункта k понадобится **второй тестовый аккаунт-читатель**. Создаёт пользователь; пароль — только в его менеджере паролей, не в файлах проекта.
