## 8. TASK-024 — управление отзывами (скрытие, ответы в кабинете)

**Коммит:** см. `tasks/REPORT.md` (TASK-024).

**Миграция `0009_comments_guestbook_hidden.sql`** (применяет пользователь):
- `is_hidden boolean not null default false` в `comments` и `guestbook_entries`;
- `comment_parent_is_visible(uuid)` — SECURITY DEFINER, проверка родителя без рекурсии RLS;
- RLS SELECT: гости/читатели видят только видимые (ответ скрыт при скрытом родителе), `is_admin()` — всё;
- RLS UPDATE только `is_admin()`; BEFORE UPDATE триггер разрешает менять **только `is_hidden`**;
- `enforce_write_rate_limit` расширен: у автора `author_name := author_display_name()` при любом insert.

**Результат применения:** ✅ применена (пользователь, SQL Editor, «Success»). Живые проверки — **все OK** (таблица в `tasks/REPORT.md`). Найден и исправлен баг: автор не мог писать в гостевую с витрины (валидация требовала имя).

**Что изменилось на витрине vs кабинет:**

| Где | Было | Стало |
|---|---|---|
| Страница рассказа (автор) | форма комментария + «Ответить» | формы нет; строка «Отвечать на отзывы — в Кабинете» → `/admin/comments` |
| Страница рассказа (все) | ответ автора — синяя плашка | имя полужирным + мелко «Ответ автора», отступ + тонкая линия |
| Кабинет «Комментарии» | удалить/бан | + **Скрыть/Показать**, бледное + «скрыт», **Ответить** (если ответа нет) |
| Кабинет «Гостевая книга» | удалить/бан | + **Скрыть/Показать**, бледное + «скрыт» |
| Вход автора | на `from` | на `from` (если `/admin…`) иначе `/admin/comments` |
| Шапка, «Кабинет» | `/admin/stories` | `/admin/comments` |
| Гостевая (автор, с витрины) | поле «Имя» | без «Имя» (подпись из БД) |
| Абзацы рассказа | по пустым строкам | каждый `\n` → абзац (пустые схлопываются) |

**Живые проверки** — таблица в `tasks/REPORT.md` (заполняется после применения 0009).
