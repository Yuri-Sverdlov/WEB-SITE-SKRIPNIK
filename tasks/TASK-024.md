## Цель

Вся **модерация и ответы автора** — только в кабинете (**«Комментарии»**, **«Гостевая книга»**). Публичные страницы рассказов **без** кнопок управления; ответы на витрине только **отображаются**. Плюс: скрытие записей, вход автора, подпись автора, вид ответа, абзацы в тексте рассказа.

**Не входит:** редактирование текста ответа; группировка/фильтр «без ответа» в кабинете; изменение логики «Удалить / Заблокировать / Удалить все» (кроме отображения скрытых).

## Зафиксированные решения

| Тема | Решение |
|---|---|
| Разделы кабинета | «Комментарии», «Гостевая книга» — скрыть/показать, ответить (только комментарии). **«Рассказы»** и формы рассказов — **без** новых кнопок модерации |
| Миграция | **`0009_*` всегда новый файл**; **`0008` не править** (применена или нет — неважно) |
| `is_hidden` на ответе | **Не выставлять автоматически**; читатель не видит ответ, если **скрыт родитель**; «Показать» родителя → ответ снова виден |
| Скрытый ответ при видимом комментарии | Автор может **скрыть свой ответ** отдельно — та же «Скрыть»/«Показать» |
| Публичные страницы | Скрытое **не показываем** (и автор на витрине видит **как читатель**). Бледное + «скрыт» — **только кабинет** |
| Ответов в гостевой | **Нет** (как сейчас) |
| Ответов на отзыв | **Один**; «Ответить» в кабинете — **только если ответа автора ещё нет** |
| Страница рассказа, автор | **Нет формы** комментария; строка **«Отвечать на отзывы — в Кабинете»** со ссылкой на **`/admin/comments`**; убрать **«Ответить»** на витрине |
| Гостевая, автор | Может писать **с витрины**: **без поля «Имя»**, подпись — **`author_display_name()`** в БД |
| Вход автора | Сразу после login: если **`from`** начинается с **`/admin`** → туда; **иначе** → **`/admin/comments`**. Уже залогиненного с `/`, `/stories/…` **не редиректить** |
| «Кабинет» в шапке | Ссылка на **`/admin/comments`** (не `/admin/stories`) |
| Подпись insert от автора | Любой insert от **`is_admin()`** в **`comments`** и **`guestbook_entries`**: **`author_name := author_display_name()`**, клиент игнорируется |
| Вид ответа на витрине | **«Александр Скрыпник»** — как имена читателей, **полужирным**; в той же строке **мелко серым** — **«Ответ автора»**; слева отступ **~2–2,5 em** + **тонкая вертикальная линия** |
| Абзацы рассказа | Сначала **inspect**, что в БД; отображение: **каждый `\n` — новый абзац**, пустые строки **схлопываются**; **редактор не менять** |
| RLS | Скрытое для гостей/читателей через **RLS**; проверка родителя — **`SECURITY DEFINER`** + **`search_path`** (избежать **infinite recursion**). **UPDATE** только **`is_admin()`**; тригger — менять можно **только `is_hidden`** |
| Push | **не делать** |

## Что сделать

### 1. SQL — `supabase/migrations/0009_comments_guestbook_hidden.sql`

1. **`is_hidden boolean not null default false`** в **`comments`** и **`guestbook_entries`**.

2. **Функция видимости** (имя на усмотрение, например `comment_visible_to_public(comment_row)` / обёртка для SELECT):
   - Строка видна анониму/читателю, если **`is_hidden = false`** и (**не ответ** OR **родитель не скрыт**).
   - У **ответа** **`is_hidden` не требуется** для скрытия от читателя при скрытом родителе — логика через **родителя**.
   - Реализация проверки родителя — **`SECURITY DEFINER`**, явный **`search_path`**, **без** рекурсивного SELECT по `comments` внутри политики «на себя».

3. **RLS SELECT** (заменить или дополнить «Публичное чтение…»):
   - **`public` / authenticated не-admin:** только видимые по правилам выше.
   - **`is_admin()`:** все строки.

4. **RLS UPDATE:**
   - Только **`is_admin()`**.
   - **BEFORE UPDATE** триgger: если не admin — отказ; если admin — разрешить изменение **только** **`is_hidden`**; остальные поля при UPDATE → **отказ** (или OLD = NEW для них).

5. В **`tasks/REPORT.md`:** текст миграции применяет **пользователь** в SQL Editor; кодер пишет **ожидаемые проверки** и место для результата («применена / не применена»).

**Не делать:** правки **`0008_author_name_fix.sql`**.

### 3. API и кабинет — «Комментарии» (`AdminComments.tsx`, `adminModeration.ts`)

- В выборку админки добавить **`is_hidden`**, **`parent_id`**, **`is_author_reply`** (что нужно для UI).

  - **«Скрыть»** / **«Показать»** (toggle **`is_hidden`**).
  - Скрытая — **бледная**, пометка **«скрыт»**.
  - У **комментария читателя** (корневой, **не** `is_author_reply`): **«Ответить»**, если **нет** дочернего ответа автора (`is_author_reply = true`); inline форма → **`insertAuthorReply`** (или аналог с **`parent_id`**, **`is_author_reply: true`**).
- **«Удалить»**, **«Заблокировать»**, **«Удалить все»** — **поведение и подтверждения как сейчас**; ответ автора удаляется/скрывается **как любая строка**.
