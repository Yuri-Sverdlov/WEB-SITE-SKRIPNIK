## 1. Что это за сайт

Сайт-портфолио писателя (Александр Скрыпник): рассказы, комментарии под рассказами, гостевая книга, кабинет автора для публикации и модерации. Читатели приходят по прямым ссылкам — поисковая оптимизация не приоритет, поэтому сайт сделан как обычное одностраничное приложение (SPA).

ТЗ: `ТЗ — сайт для писателя.md`. Текущее состояние и решения: `CONTEXT.md`. История: `PROJECT_LOG.md`.

## 2. Как устроено

```
Браузер читателя
   │  1. загружает сайт (HTML + JS + CSS)
   ▼
Vercel ── раздаёт собранный сайт из ветки main репозитория GitHub
   │
   │  2. дальше браузер сам ходит в Supabase (публичный ключ + JWT вошедшего)
   ▼
Supabase
   ├─ Auth      — регистрация и вход (email + пароль), подтверждение почты
   ├─ Postgres  — рассказы, комментарии, гостевая, роли; защита правилами RLS
   └─ Storage   — картинки к рассказам (bucket `illustrations`)
```

Собственного сервера нет. **Вся защита данных — в Postgres**: правила RLS, триггеры, функции с проверкой `is_admin()`. Проверки в интерфейсе (скрыть кнопку, показать «Нет доступа») — только удобство. Публичный ключ Supabase открыт намеренно (он есть в браузере и в `.env.example`), поэтому любая новая таблица **обязана** иметь RLS.

| Слой | Технология |
|---|---|
| Фронтенд | React 19 + Vite + TypeScript + Tailwind CSS 3, react-router-dom |
| Бэкенд | Supabase (Auth, Postgres, Storage), клиент `@supabase/supabase-js` |
| Хостинг | Vercel (тариф Hobby), автодеплой из `main` |
| Репозиторий | https://github.com/Yuri-Sverdlov/WEB-SITE-SKRIPNIK (публичный) |

## 3. Структура кода

```
src/
  api/         запросы к Supabase: stories, comments, guestbook, auth, admin, messageErrors
  components/  общие компоненты (ленты и формы сообщений, карточки, вкладки)
  contexts/    AuthProvider — сессия, useAuth()
  hooks/       useIsAdmin() — вызов RPC is_admin
  pages/       страницы сайта; pages/admin/ — кабинет автора
supabase/
  migrations/  SQL-миграции 0001…, применяются вручную (раздел 6)
tasks/         процесс разработки: TASK, REPORT, архив done/, брифы консультанта
vercel.json    переадресация всех путей на index.html (иначе 404 на прямых ссылках)
```

Тексты ошибок для пользователя — по-русски, перевод ошибок Supabase в `src/api/messageErrors.ts` и `src/api/auth.ts`.

## 4. Запуск на своём компьютере

```powershell
git clone https://github.com/Yuri-Sverdlov/WEB-SITE-SKRIPNIK.git
cd WEB-SITE-SKRIPNIK
npm install
Copy-Item .env.example .env.local     # bash: cp .env.example .env.local
npm run dev                           # http://localhost:5173
```

Проверки перед коммитом: `npm run build` (должен быть exit 0) и `npm run lint`.

`.env.local` в git не попадает. Нужны две переменные: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (публичный ключ, значения — в `.env.example`). **Секретный ключ Supabase (service_role) в проект не класть никогда** — ни в `.env`, ни в код.

Локальная версия и сайт на Vercel работают с **одной и той же базой**. Тестовые данные, созданные локально, видны на живом сайте.

## 5. Деплой (Vercel)

- Каждый push в `main` автоматически собирается и публикуется на https://web-site-skripnik.vercel.app.
- Переменные окружения заданы в Vercel: проект → Environment Variables (обе `VITE_*`, для Production и Preview). Vite вшивает их **при сборке**: после изменения переменных нужен Redeploy (Deployments → ⋯ → Redeploy).
- `vercel.json` переадресует все пути на `index.html`. Без него прямая ссылка на рассказ и обновление страницы (F5) дают 404.
- Вход в Vercel — через GitHub-аккаунт владельца репозитория.

## 6. База данных (Supabase)

### Миграции

Папка `supabase/migrations/`, номера по порядку. Применяются **вручную**: Supabase Dashboard → SQL Editor → вставить файл → Run. Файлы написаны идемпотентно (повторный запуск не ломает). `0001_baseline.sql` — снимок исходной схемы, на живую базу не применяется.

| Файл | Что делает |
|---|---|
| 0001 | Снимок исходного состояния: `stories`, функция счётчика просмотров |
| 0003 | `comments`, `guestbook_entries`: колонки, ограничения длины, лимит 3 сообщения в минуту |
| 0004 | Сервер сам задаёт `created_at` и `is_author_reply` (защита от подделки) |
| 0005 | Роль автора, права записи, ответы автора, бан, функции модерации |
| 0006 | Политики Storage для bucket `illustrations` (bucket создаётся вручную в Dashboard) |
| 0007 | Профили читателей: постоянный уникальный никнейм (в работе, TASK-017) |

### Таблицы

| Таблица | Назначение | Кто пишет |
|---|---|---|
| `stories` | Рассказы: заголовок, текст, дата, теги, иллюстрации (массив URL), `views_count` | только автор |
| `comments` | Комментарии; `parent_id` + `is_author_reply` — ответ автора (один уровень) | вошедшие читатели; удаляет автор |
| `guestbook_entries` | Гостевая книга | вошедшие читатели; удаляет автор |
| `site_admins` | Кто автор (может быть несколько) | только через SQL Editor |
| `banned_users` | Заблокированные читатели (`user_id`, `banned_at`, `reason`) | автор |
| `reserved_author_names` | Имена, которые читатель не может взять («скрипник», «админ» …) | через SQL Editor |
| `reader_profiles` | Никнейм читателя (с 0007) | читатель — один раз |

### Ключевые функции и триггеры

- `is_admin()` — единственная точка проверки «автор ли текущий пользователь». Используется в RLS, триггерах, RPC.
- `author_display_name()` — подпись автора («Александр Скрыпник»). Для другого сайта меняется только эта функция.
- `normalize_author_name(text)` — нижний регистр, ё→е, латинские двойники → кириллица. Для проверки запрещённых и занятых имён.
- `enforce_write_rate_limit()` — триггер перед вставкой в `comments` и `guestbook_entries`: отказ гостю и забаненному, `created_at := now()`, обнуление служебных полей у читателя, запрещённые имена, лимит 3 в минуту (автор освобождён).
- `admin_count_user_messages(uuid)`, `admin_delete_user_messages(uuid)` — счёт и удаление всех сообщений читателя (только автор).
- `increment_story_views(uuid)` — счётчик просмотров (вызывается при открытии рассказа).

### Почта и вход

- В Supabase включено **подтверждение email** при регистрации.
- Используется **встроенная почта Supabase** — она для тестов: отправляет очень мало писем и может доставлять их не на все адреса. **Перед запуском для читателей** нужно подключить свой SMTP (Authentication → SMTP Settings).
- **Страницы «задать новый пароль» на сайте нет.** Ссылка «Забыли пароль?» отправляет письмо, но сменить пароль после перехода негде. Пока пароль меняется через SQL (раздел 8).

## 8. Шпаргалка SQL (Supabase → SQL Editor)

Для `update`, `insert`, `delete` редактор пишет «Success. No rows returned» — это **нормально**, значит команда не возвращает таблицу. Результат проверяйте отдельным `select`.

**1. Кто сейчас автор**
```sql
select u.email, s.created_at
from public.site_admins s
join auth.users u on u.id = s.user_id;
```

**2. Выдать права автора** (человек должен сначала зарегистрироваться на сайте)
```sql
insert into public.site_admins (user_id)
select id from auth.users where email = 'EMAIL'
on conflict do nothing;
```

**3. Передать права другому человеку** — выполнить команду 2 с новым email, проверить командой 1, затем снять права со старого:
```sql
delete from public.site_admins
where user_id = (select id from auth.users where email = 'СТАРЫЙ_EMAIL');
```

**4. Подтвердить почту вручную** (если письмо не пришло)
```sql
update auth.users
set email_confirmed_at = now()
where email = 'EMAIL' and email_confirmed_at is null;
```

**5. Задать новый пароль** (латиница, без пробелов) и сразу проверить
```sql
update auth.users
set encrypted_password = extensions.crypt('НОВЫЙ_ПАРОЛЬ', extensions.gen_salt('bf', 10))
where email = 'EMAIL';

select extensions.crypt('НОВЫЙ_ПАРОЛЬ', encrypted_password) = encrypted_password as password_ok
from auth.users where email = 'EMAIL';
```
Ожидается `password_ok = true`.

**6. Заблокировать / разблокировать читателя** (обычно это делает автор кнопками в `/admin`)
```sql
insert into public.banned_users (user_id, reason)
select id, 'причина' from auth.users where email = 'EMAIL'
on conflict do nothing;

delete from public.banned_users
where user_id = (select id from auth.users where email = 'EMAIL');
```

**7. Завести тестового читателя для экспериментов.** Через SQL аккаунт не создавать — зарегистрироваться на сайте. Удобно использовать «плюс-адрес» Gmail: `ваш.ящик+reader2@gmail.com` (письма придут в основной ящик, Supabase считает адрес новым). Затем подтвердить почту командой 4. Удалить тестового читателя: Dashboard → Authentication → Users → пользователь → Delete user. Его комментарии и записи гостевой удалятся вместе с ним.

## 9. Процесс разработки

Роли: **консультант** (бриф блока, итоговая проверка) → **пользователь** (решения, применяет SQL) → **архитектор** (пишет `tasks/TASK.md`, принимает работу) → **кодер** (реализует, пишет `tasks/REPORT.md`). Одно активное задание за раз; принятые — в `tasks/done/NNN-…/`. Push — только после подтверждения пользователя. Правила кодера — `AGENTS.md`.

Проект ведётся на двух компьютерах; в документах пути помечаются `[ПК1]` / `[ПК2]`. **Первое действие сессии — `git pull`, последнее — push.**

## 10. Известные ограничения и долги

- Встроенная почта Supabase и нет страницы смены пароля (раздел 6).
- Основной JS-файл ~500 КБ (предупреждение сборщика) — при росте можно разбить на части.
- Нет индекса `comments(story_id)` — добавить при росте числа комментариев.
- Предупреждения lint `set-state-in-effect` / `exhaustive-deps` в нескольких хуках — известны, не ошибки.
- Нет адаптивной вёрстки, SEO, тёмной темы и др. — список «MVP-2» в ТЗ, раздел 8.
- Перенос 200+ рассказов с Проза.ру — отдельный этап после запуска (ТЗ, раздел 7).

## 11. Как сделать сайт №2 или №3

1. Новый репозиторий из этого кода, новый проект Supabase, новый проект Vercel.
2. Применить миграции 0003 и далее по порядку; таблицу `stories` создать по `0001_baseline.sql`.
3. Поменять подпись автора в `author_display_name()` и список в `reserved_author_names`.
4. Создать bucket `illustrations` в Storage, применить 0006.
5. Прописать `VITE_*` нового проекта в `.env.local` и в Vercel.
6. Автор регистрируется на сайте → подтвердить почту (команда 4) → выдать права (команда 2).
