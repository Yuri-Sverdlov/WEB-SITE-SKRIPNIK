# Техническое задание — сайт для писателя

2026-09-19 · @Someone

## 1. Обзор проекта

**Цель:** сайт-портфолио для автора рассказов — витрина текстов с обратной связью от читателей.

**Объём:** пилотный проект; после запуска — ещё 1–2 аналогичных сайта по той же схеме (архитектура и код переиспользуются).

**Формат:** веб-сайт. Адаптивная вёрстка и SEO-разметка вынесены в MVP-2 (раздел 8).

**Контекст:** у автора уже 200+ рассказов на Проза.ру. Их перенос на новый сайт — отдельный этап после запуска (раздел 7), не входит в MVP.

## 2. Структура страниц и навигация

| Страница | Назначение |
| --- | --- |
| Главная / Об авторе | Биография, фото, контакты в соцсетях |
| Рассказы | Список с подменю и страницами отдельных рассказов — детали в разделе 3 |
| Связь | Форма связи/контактные данные |
| Гостевая книга | Стандартный редактор записей, красиво оформленный, требует регистрации |

**Меню раздела «Рассказы»** (три вкладки/фильтра внутри одного раздела, не отдельные URL-страницы по смыслу):

- Новые
- Популярные
- Все

**Категории версус теги:** категория — это раздел навигации для разных типов контента (например, «Рассказы» / «Повести» / «Стихи») — один раздел на объект. Теги — свободные метки для тематического поиска внутри одного типа (можно навесить несколько на один рассказ: «любовь», «ностальгия», «юмор»). Если на сайте будут только рассказы одного формата — **категории не нужны, достаточно тегов/жанров**. Если появятся стихи или эссе — потребуются категории.

## 3. Раздел «Рассказы»

**Новые:** рассказы, опубликованные за последние 365 дней от текущей даты — скользящее окно, без привязки к 1 января.

**Популярные:** сортировка по числу просмотров. Начальное значение счётчика — реальные просмотры с Проза.ру на момент переноса (вносится вручную при добавлении рассказа). Далее счётчик увеличивается на +1 при каждой загрузке страницы (простая схема без real-time, как ты и подтвердил).

**Все:** полный список, сортировка по дате или алфавиту (уточним позже). Пагинация — по 15 рассказов на странице, с кнопками постраничной навигации.

**Поиск:** по названию и по тексту рассказа (полнотекстовый поиск). При 200+ рассказах простой SQL LIKE-поиск справится; полнотекстовый индекс (типа Postgres full-text search) — только если понадобится релевантность/скорость.

**Теги/жанры:** свободные метки, несколько на рассказ; фильтр по тегу на странице «Все».

**Страница отдельного рассказа:** текст, иллюстрации, дата публикации, счётчик просмотров, теги, блок комментариев внизу (раздел 4).

## 4. Комментарии, гостевая книга, регистрация

**Комментарии под рассказом:** публичная лента, видна всем посетителям. Автор может отвечать на любой комментарий (один уровень вложенности — ответы на ответы не нужны для MVP). Это **не** чат в реальном времени — обычная форма отправки с загрузкой страницы.

**Регистрация читателей:** обязательна для комментариев и гостевой книги. Минимально для MVP: email + пароль или вход через Google/Яндекс (OAuth упрощает регистрацию и снижает спам без капчи — **открытый вопрос: какой вариант выбираем**, см. раздел 8).

**Гостевая книга:** стандартный редактор записей (имя + текст), лента всех записей, требует авторизации. Оформление по макету сайта.

**Защита от спама:** три рубежа защиты:

1. Регистрация обязательна — уже отсекает большинство автоматических ботов.
2. Rate limiting на отправку (не чаще N сообщений в минуту с одного аккаунта).
3. Модерация вручную в админке — автор может удалить любой комментарий/запись.

Автоматическая фильтрация мата (на movable-type или простой список стоп-слов) — отложена, не критична при регистрации + ручной модерации.

## 5. Backend и администрирование

**MVP-версия редактора** (как ты и просил):

- Форма с полями: заголовок, текст (textarea с поддержкой абзацев), дата публикации, теги, загрузка иллюстраций (drag-n-drop или простой file input).
- Доступ только автору (отдельный логин, не через общую регистрацию читателей).
- Редактирование/удаление уже опубликованных рассказов.

**Полноценный редактор (позже, не в MVP):** WYSIWYG с форматированием (жирный/курсив, вставка изображений внутри текста, черновики/автосохранение, предпросмотр перед публикацией).

**Хранение данных:** база данных (рассказы, комментарии, пользователи, счётчики просмотров) + отдельное хранилище для изображений (файловая система или S3-совместимое хранилище — выбор зависит от хостинга, уточнить при выборе платформы).

## 7. План автоматизации переноса (после запуска MVP)

1. **Парсинг с Проза.ру:** скрипт собирает список рассказов автора (заголовок, текст, дата публикации, текущее число просмотров).
2. **Очистка:** удаление служебной верстки сайта-источника, приведение к единому формату.
3. **Импорт:** запись в базу данных нового сайта через тот же API, что использует админка — чтобы не делать отдельный путь записи в БД.
4. **Начальные просмотры:** переносятся вручную как стартовое значение счётчика на момент переноса.

**Важно:** этот этап намеренно отложен до запуска основного сайта — 200+ рассказов без готовой структуры сайта переносить бессмысленно.

## 9. Этапы разработки (для передачи архитектору)

Схема работы: я (консультант) даю этап → ты передаёшь его архитектору (Cursor Composer) → архитектор дробит его на задачи для кодера. Каждый этап проверяется визуально (скриншот в браузере) перед переходом к следующему.

0. **Инициализация:** Vite + React + TS + Tailwind, репозиторий на GitHub, деплой пустой страницы на Vercel — проверить, что весь конвейер работает.
1. **Каркас:** пустые страницы (Главная, Рассказы, Связь, Гостевая книга) и навигация между ними.
2. **Supabase:** создать проект, спроектировать таблицы (stories, users, comments, guestbook), подключить к фронтенду.
3. **Список рассказов:** три вкладки (Новые/Популярные/Все) на моковых данных, пагинация 15/страница.
4. **Страница рассказа:** текст, иллюстрации, счётчик просмотров (+1 при загрузке).
5. **Регистрация читателей:** email+пароль через Supabase Auth.
6. **Комментарии:** форма, лента комментариев, ответ автора.
7. **Гостевая книга:** форма + лента записей.
8. **Backend-редактор для автора:** форма добавления/редактирования рассказа с загрузкой иллюстраций.
9. **Защита от спама:** rate limiting на отправку форм + модерация в админке.
10. **Визуальная доводка:** по макету (когда пришлёшь) + перенос на постоянный домен.
