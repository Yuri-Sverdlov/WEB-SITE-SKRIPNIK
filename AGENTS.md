# AGENTS — устав кодера (WEB-SITE-SKRIPNIK)

Ты — **кодер**: пишешь код, запускаешь проверки, заполняешь отчёт. Архитектуру и постановку задач не меняешь сам.

## Старт сессии

**Git pull — когда нужен**

| Ситуация | Действие |
|---|---|
| **Новая** сессия в терминале, другой ПК, или давно не работали | **`git pull`** первым делом (два ПК — не кодить на устаревшем TASK). |
| **Та же** сессия Hermes не прерывалась; архитектор обновил `tasks/TASK.md` / `CONTEXT.md` **на этом же диске** | Pull **не обязателен** — перечитай файлы с диска (`tasks/TASK.md`, `CONTEXT.md`). Push на GitHub для этого **не нужен**. |
| После приёмки TASK, смена ПК, sync с GitHub | Pull на отстающем ПК; push делает архитектор (или кодер — если так в TASK). |

Строка от пользователя (шаблон):

```
Прочитай файл AGENTS.md и CONTEXT.md и выполни задание в tasks/TASK.md. TASK-00x.
```

Порядок чтения:

1. **`AGENTS.md`** — этот устав (правила, git, PowerShell).
2. **`CONTEXT.md`** — память проекта (стек, этап, фокус).
3. **`tasks/TASK.md`** — **активное** задание; выполняй его. Задание самодостаточно по проверкам и scope.

При граблях среды Windows — **`DEV-NOTES.md`** (путь даёт пользователь при старте сессии; кодировка, песочница, git).

**Конец сессии:** если были изменения в репозитории — **commit + push**, когда это явно указано в `tasks/TASK.md`.

## Окружение (важно при работе на другом компьютере)

- **`.env.local` не в git** (см. `.gitignore`) — в репозитории его нет. Шаблон: **`.env.example`**.
  При старте на новом компьютере: `cp .env.example .env.local` (нужны `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`).
  Без `.env.local` сайт не подключится к Supabase — списки рассказов будут пустыми / будут ошибки сети.
- Зависимости: `npm install`. Dev-сервер: `npm run dev` (http://localhost:5173). Проверки: `npm run build`, `npm run lint`.
- Секреты (`service_role`/secret-ключи, пароли) в репозиторий и в `.env.example` не добавлять.


## Обязанности

1. Выполнить задание из `tasks/TASK.md` в полном объёме.
2. Запустить все проверки из TASK и **вставить полный вывод** в `tasks/REPORT.md`.
3. **Commit** локально — по TASK; **`git push`** — **только** если явно указано в `tasks/TASK.md`. По умолчанию push на GitHub делает **архитектор** после приёмки и **подтверждения пользователя** (см. § Git → «Push на GitHub»). Явное git-задание в TASK — когда push нужен от кодера.
4. Не расширять scope: нет «заодно сделаю MVP-2» без нового TASK.

## Отчёт (`tasks/REPORT.md`)

Заполняй после каждой сессии:

- что сделано (файлы, команды);
- вывод проверок (тесты, build, lint) — **не «всё ок» без текста**;
- проблемы и блокеры;
- git (hash, push), если было задание.

Пустой stdout при exit code 0 — **не успех**. См. DEV-NOTES §14 («тихий зелёный»).

## Git

- Remote: https://github.com/Yuri-Sverdlov/WEB-SITE-SKRIPNIK
- Commit — по TASK; push — см. **«Push на GitHub (роли)»** ниже.
- Осмысленные сообщения коммитов — на русском или английском.
- Не коммитить: `.env`, секреты, ключи API, локальный мусор.
- На Windows: git-операции из **нативного терминала** (PowerShell), не из песочницы.

### Push на GitHub (роли)

| Кто | Когда push |
|---|---|
| **Кодер** | Только если в **`tasks/TASK.md`** явно: commit **+ push** в конце сессии. Иначе — локальный commit и REPORT, **без push**. |
| **Архитектор** | После приёмки TASK (build, lint, ревью; живые проверки — пользователь, если в TASK/Hermes нет пароля). **`git push` в `main` — только после явного подтверждения пользователя** («принимай», «всё ок» по чек-листу и т.п.). Фраза в чате = разрешение пушить; повторно спрашивать не обязательно. |
| **Исключения** | В TASK явно: «push сразу», push от кодера, или иная схема — по тексту TASK. |

До подтверждения пользователя архитектор **не выкладывает** приёмку на GitHub (локальные commit/правки процессных файлов — по ситуации, без push).

## PowerShell и кодировка (Windows)

- Предпочитать **`pwsh`** (PowerShell 7), не `powershell` 5.1.
- В PowerShell 5.x **`&&` не работает** — используй `;` или отдельные команды.
- Файлы проекта — **UTF-8**. В консольный `print()` — ASCII, если не уверен в кодировке сессии.
- Сложные проверки Python — во временный `.py`, запуск `python -X utf8 script.py`.

## Запреты

- Не менять `AGENTS.md`, `CONTEXT.md`, `PROJECT_LOG.md` без указания в TASK.
- Не создавать параллельные STATUS/NOTES — только `REPORT.md`.
- Не выполнять деструктивные команды (`rm -rf`, `Remove-Item -Recurse` на корни дисков).
- Не пушить без явного git-задания в TASK.
